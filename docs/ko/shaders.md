## 셰이더

*GPU에서 실행되는 프로그램.* **3D 아티스트에게 흔한 디스플레이 시스템** — 객체에 적용되는 동적 텍스처를, 실행 중에, 픽셀 단위로, 병렬로 계산합니다. 색을 미리 굽는 대신, 셰이더는 매 프레임마다 모든 픽셀의 색을 계산합니다. 바로 이것이 애니메이션되고 반응하며 절차적으로 생성되는 비주얼을 가능하게 합니다.

이 사이트의 배경 자체가 수십 개의 탐색 가능한 프로그램을 갖춘 맞춤형 WebGL2 셰이더 시스템 위에서 실행됩니다.

### 셰이더는 무엇으로 이루어지는가

- **버텍스 셰이더** — 버텍스마다 한 번 실행되며, 지오메트리의 각 점이 화면의 어디에 놓일지(위치와 파이프라인 아래로 내려가는 변수)를 정합니다.
- **프래그먼트 셰이더** — 픽셀마다 한 번 실행되며, 보간된 변수, 유니폼, 텍스처, 수학으로 최종 색을 정합니다.
- **유니폼** — CPU 쪽에서 드로 콜마다 설정되는 값(시간, 마우스, 해상도)으로, 드로의 모든 픽셀이 공유합니다.
- **어트리뷰트 / 베리잉** — 지오메트리에서 오는 버텍스 단위 입력으로, 버텍스와 프래그먼트 단계 사이에서 표면에 걸쳐 보간됩니다.

### 왜 여기서 중요한가

이 사이트가 쓰는 모든 비주얼 — 애니메이션 배경, 전환, 그레인, 생성적 표면 — 은 실시간으로 도는 셰이더입니다. 맞춤 시스템 덕분에 정적인 하나의 굽힌 룩을 내놓는 대신 수십 개의 탐색 가능한 프로그램을 실어 나르고 그 사이를 라이브로 전환할 수 있습니다.

```glsl
// a minimal fragment shader — a background that shifts with time
#version 300 es
precision highp float;
uniform float uTime;
out vec4 outColor;
void main(){
    float wave = 0.5 + 0.5 * sin(uTime * 2.0 + gl_FragCoord.x * 0.01);
    outColor = vec4(vec3(wave, 0.4, 0.6), 1.0);
}
```

### 어디에 맞는가

- **배경 프로그램** — 이 페이지에서 내비게이션으로 전환하며 보게 되는 셰이더들.
- **전환과 표면** — 콘텐츠 섹션 위에 겹쳐진 이펙트.
- **내보내기** — 같은 GLSL 개념이 실시간 엔진과 렌더러로 그대로 이어집니다.
