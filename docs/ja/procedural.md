## プロシージャル

*生成的で動的な制作ワークフロー。* **手で作るのではなく — 数学と物理によって計算される。** すべてのディテールを手作業で配置する代わりに、ルールやアルゴリズムが結果を構築するため、同じロジックが無限のバリエーションを生み出せます。

手作業モデリングの反対です。プロセスを一度書けば、あとは形を生成させます。

### 何をもたらすか

- **生成的な出力** — 手動配置ではなく、パラメータ（シード、スライダー、入力）からジオメトリ、マテリアル、シーン全体を生み出すレシピ。
- **タダで得られるバリエーション** — シードや値を一つ変えるだけで、新しくも一貫した結果が得られます。反復と探求に最適です。
- **道具としての物理と数学** — 力、ノイズ、成長規則、制約が、アーティストの手ではなく結果を形作ります。
- **再現性** — 同じプロセスを二度実行すると同じ（または意図的に変化した）結果が得られ、シリーズやシステムに最適です。

### なぜここでのアプローチなのか

**Ashina** のようなツール — Blender Geometry Nodesで作られたアジア建築ジェネレーター — はこのアプローチの良い例です。屋根や塔を一つずつ手でモデリングする代わりに、ツールが建築のルールをコード化し、そこからフォルムを生成します。

```python
# the idea, in pseudo-code
def roof(config):
    # a rule describes how a roof builds itself
    return [
        generate_curve(config["width"], config["curvature"]),
        extrude_along(curve),
        tile_surfaces()          # then material & shader take over
    ]

for seed in range(10):
    build(roof(roofs(seed)))     # ten variations, one recipe
```

### どこに位置づけられるか

- **Ashina** — 屋根のジェネレーター: 建築のルールをデータとして。
- **シェーダー** — シェーダー自体がプロシージャルです。フラグメントプログラムは *まさに* ピクセルを生成するルールです。
- **作品** — 単一のオブジェクトではなく、形のファミリーを探求するシリーズ。
