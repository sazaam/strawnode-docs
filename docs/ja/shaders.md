## シェーダー

*GPU上で実行されるプログラム。* **3Dアーティストに一般的な表示システム** : オブジェクトに適用される動的テクスチャを、その場で、フラグメントごとに、並列に計算します。色を事前に焼き込む代わりに、シェーダーは毎フレームすべてのピクセルの色を計算します — これがアニメーションし、反応し、プロシージャルに生成されるビジュアルを可能にします。

このサイトの背景自体が、数十のナビゲート可能なプログラムを備えたカスタムWebGL2シェーダーシステムの上で動いています。

### シェーダーは何でできているか

- **バーテックスシェーダー** — 頂点ごとに一度実行され、ジオメトリの各点が画面上のどこに来るか（位置、およびパイプラインに渡される変数）を決めます。
- **フラグメントシェーダー** — ピクセルごとに一度実行され、補間された変数、ユニフォーム、テクスチャ、数学から最終的な色を決めます。
- **ユニフォーム** — ドローコールごとにCPU側から設定される値（時間、マウス、解像度）で、そのドローのすべてのピクセルが共有します。
- **アトリビュート / バリイング** — ジオメトリからの頂点単位の入力で、バーテックス段階とフラグメント段階の間で表面にわたって補間されます。

### なぜここでシェーダーが重要か

このサイトが頼っているすべてのビジュアル — アニメーションする背景、トランジション、グレイン、生成的な表面 — はリアルタイムで動くシェーダーです。カスタムシステムなら、静的な焼き込みのルックを一つ出す代わりに、数十のナビゲート可能なプログラムを届け、その間をライブで切り替えられます。

```glsl
// a minimal fragment shader — a background that shifts with time
#version 300 es
precision highp float;
uniform float uTime;
out vec4 outColor;
void main(){
    float wave = 0.5 + 0.5 * sin(uTime * 2.0 + gl_FragCoord.x * 0.01);
    outColor = vec4(vec3(wave, 0.4, 0.6), 1.0);
}
```

### どこに位置づけられるか

- **背景プログラム** — このページで見えるシェーダーで、ナビゲーションを通じて切り替わります。
- **トランジションと表面** — コンテンツセクションの上に重ねられるエフェクト。
- **エクスポート** — 同じGLSLの考え方がリアルタイムエンジンやレンダラーにもそのまま活きます。
